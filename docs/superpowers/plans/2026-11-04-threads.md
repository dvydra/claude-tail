# Threads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Long-running named threads of work in the Obsidian vault, a morning triage TUI (`entire-tail threads`) to open, park and close them, and a shared agent skill that updates a thread on handover.

**Architecture:** Go owns the files, the TUI, live checks and every write to frontmatter/registry, exposed as `entire-tail threads <subcommand>` so agents never hand-edit machine state. Agents (Claude and Amp) write the prose through one shared skill, `thread-handover`, and commit it through `entire-tail threads commit`, which refuses a stale base. The handover paths keep writing dated docs until a switch file is created after the bootstrap.

**Tech Stack:** Go 1.24 single `package main`, glamour for prose, `gopkg.in/yaml.v3` for frontmatter (new, compiled in; no runtime dependency), `syscall.Flock`, osascript via existing `iterm.go`.

**Spec:** `docs/superpowers/specs/2026-11-04-threads-design.md`

## Global Constraints

- Vault root: `firstNonEmpty(getenv("ENTIRE_TAIL_HANDOVER_VAULT"), defaultHandoverVault)` (`handover.go`). Threads live at `<root>/Entire/Threads/`, closed ones at `<root>/Entire/Threads/_closed/`.
- Per thread: `thread.md`, `knowledge.md`, `log/YYYY-MM-DD.md`. Registry `<Threads>/.registry.json`. Lock file `<Threads>/.lock`, never unlinked. Cutover switch `<Threads>/.enabled`.
- Only this machine writes. A local `flock` is enough.
- `thread.md` sections, in order, exact headings: `## What it is`, `## Where it got to`, `## What's in the way`, `## People`, `## Recent`.
- Section older than 7 days is dimmed and labelled `as of <date>`. "Recent" holds the last 3 working days.
- List-line precedence: (1) `stale: <claim> disagrees with <source>`, (2) a Go-detected live risk, (3) written `waiting_on`.
- Nothing changes thread status without Daniel: no auto park, unpark, close or reopen.
- Go never calls a model. Tests never touch the real vault, iTerm, launchd or git outside temp dirs: every IO step is a package var.
- No em dashes in any written copy. `go vet ./... && go test -race ./...` clean; goldens unchanged.

## Deviation from the spec (tell Daniel)

- **Linear claims are not checked by Go in the first build.** Go has no Linear access (that lives in the agents' MCP). The `linear` claim kind is stored and shown under `d`, but not checked. Worktree and trail claims are checked.
- **`⏎` on a thread with no session starts a fresh agent** with the prompt `Read <path>/thread.md and knowledge.md, then continue this thread.` Otherwise it resumes the newest registered session (the spec left resume vs fresh to the builder).

## Review Focus

1. A `thread.md` hand-edited in Obsidian with broken or missing frontmatter: the thread still lists, with `unreadable: <error>` as its status, and is never dropped or overwritten by Go. (Task 1)
2. A worktree in a claim that has been deleted (normal end of a worktree): the check reports `stale: worktree gone`, not an error, and the screen still opens. (Task 4)
3. Two agents committing the same thread: the second `commit` with an old base is refused with exit code 3 and prints the current version, and no update is lost. (Task 3)
4. A thread name with spaces, slashes, capitals or emoji: the slug is safe and stable, and a second thread with the same slug is refused, not merged. (Task 1)
5. No `Threads/` folder yet, or an empty one: the screen opens with `no threads yet: run /handover in a session to start one`. (Task 5)
